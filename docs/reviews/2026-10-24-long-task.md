# Long-task validation with GLM 5.3

Date: 2026-10-24 (Asia/Shanghai). Sope baseline: `2e9182f`.
Platform: macOS arm64, Bun 1.3.11. This is a local sope development experiment,
not a release or a MatrixOne production patch.

## Workload and isolation

Read Loom's module-test workflow and used sope directly: Loom currently has no
sope runtime adapter. Exported MatrixOne source commit
`35e873a261b0b50ebbffe84b4264c65f42dc32e7` to a separate snapshot, leaving the
original checkout and Loom runtime untouched. The outer bytejson package needs
native dependencies unavailable in this environment; the final workload uses
its actual pure-Go dependency `pkg/internal/bytejsonvalidate`.

The GLM 5.3 workload reads implementation/callers, writes boundary tests, runs
package tests and fuzzing, then records commands, results and limitations.
Tests execute production code, not a replacement implementation. Final runs
use auto permissions. An earlier full-permission run attempted to install a
native dependency; it was stopped and that newly installed package was removed.

## Confirmed sope issues and fixes

| Issue | Evidence | Result |
| --- | --- | --- |
| Failed proactive compaction repeats after every tool round | Live summary attempts failed after 342,937 ms and 51,327 ms, and ordinary tool progress immediately triggered another summary | Suppress proactive compaction after failure for the remainder of the turn. Preserve all history and enforce the hard context budget. New input/manual compaction can retry; bounded server-overflow recovery remains available. |
| Print-mode termination leaves shell work running | Process fixture reproduced a live shell after SIGTERM on the original code; closed-pipe exit also bypassed cleanup | SIGINT/SIGTERM/SIGHUP and EPIPE cancel and drain the agent before shutdown. Tests assert both exit status and shell death. |
| TUI event trace loses lifecycle context and shifts its array for every fragment | 10,000 adjacent streaming fragments evicted lifecycle entries; each excess event shifted the 2,000-entry buffer | Coalesce adjacent stream fragments by origin and type into byte/chunk counts; use a fixed ring and bounded previews. |

No P0 was confirmed. The findings concern reliability and diagnostic cost.

The resumed workload also issued two edits to the same file in one batch. The
second correctly failed its captured-revision check, but the diagnostic blamed
only the user or an external program. Edit/write descriptions now tell the
model to sequence same-file mutations, and the failure message includes other
tool calls. The revision guard remains intact; this is a guidance correction,
not evidence of a lost update.

## Trace contract and measured cost

`SOPE_TRACE_DIR` enables one private JSONL file per bridge lifetime. The records
contain lifecycle IDs, durations, provider attempts/status, byte/token counts
and a 15-second heartbeat. They omit text, reasoning, tool payloads, credentials,
URLs and raw errors. Async output has a 256 KiB queue and 64 MiB file cap;
gap/limit markers make truncation explicit. Journals remain the recovery source.

The completed durable GLM run lasted 379.342 seconds: 11 tool executions,
10 completed model calls and 3 transport retries. Its trace has 111 records /
29,284 bytes. Shutdown drained successfully with zero active spans. Another
run encountered a streaming transport timeout after about 353 seconds; it
ended with an error and also drained correctly, rather than hanging the host.

Local event-panel microbenchmark, one warmup plus five samples (median):

| Workload | Baseline | Fixed |
| --- | ---: | ---: |
| 200,000 streaming fragments | 61.980 ms | 8.359 ms |
| 100,000 metadata entries | 27.291 ms | 11.860 ms |

These measure trace processing, not end-to-end model response time.

## Workload outcome and recovery

The first generated tests passed but code review found inaccurate key-boundary
construction and a fuzz callback that stopped traversal early. Passing tests
were not accepted as sufficient evidence. Reopened the same durable journal
and asked sope to correct these tests. One follow-up reached its six-minute
host deadline while waiting for the model; cancellation drained cleanly. The
next reopen completed in 250.175 seconds, with 9 tool executions and a normal
`end_turn`. It corrected the inputs, ran the requested tests and updated the
report without changing the production implementation.

Verified actual journaled tool results, not just the model's final claims:

- Three added `TestLoom*` tests: 3/3 passed, exit 0.
- Whole `pkg/internal/bytejsonvalidate` test suite: passed, exit 0.
- `go test -count=1 -timeout=60s -parallel=2 -fuzz=FuzzLoomContainer
  -fuzztime=30s ./pkg/internal/bytejsonvalidate`: passed, exit 0;
  6,788,110 executions in about 30 seconds.
- `validate.go` matches the source commit byte for byte. No MatrixOne
  production bug was confirmed; the corrected defects were in generated tests.

The three durable host lifetimes recorded 261 rows / 68,746 bytes over 989.530
seconds of active execution. All ended with successful drain and zero active
spans. Comparing those traces with the configured API key found zero matches.
The final model report's historical failure count and fuzz-bound wording were
also corrected against the actual evidence; the original report was retained
separately in the local evidence directory.

Tests, journals and raw execution evidence stay in the separate local snapshot
and evidence directories under `.loom/tmp/sope-long-task*`; they are not part
of this commit or a published release.
